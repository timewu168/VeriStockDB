🗺️ VeriStockDB 雙軌數據防禦修改規劃
1. 定義數據時空區隔（舊資料 vs 新資料）
舊資料判定標準：欲處理的資料月份不是當前月份，且目標日期距離今天大於 30 天以上。

新資料判定標準：不符合上述條件者（即當月資料，或 30 天內之近端資料）。

2. 歷史舊資料下載工作流（雙源月曆導引模式）
動態記憶體月曆：當啟動歷史區間更新（如補抓 2022 年資料）時，系統改以「月份」為迭代單位。

按月請求真理：

每個月份開始前，先發送一次 STOCK_DAY (0050) API 取得該月整包 JSON。

解析出該月所有真實存在的交易日清單（西元化、去逗號）。

精準下載與優雅跳過：

歷史下載迴圈只對該清單內的真實交易日發送上市/上櫃 CSV 請求。

不在清單內的休市日、颱風假，直接優雅跳過（Elegant Skip），完全不請求，杜絕任何單邊缺失或 2KB 空檔造成的誤判中斷。

跨月滾動：當日期指標跨入下一個新月份，才再次觸發 API 抓取新月份的 0050 對照組。

3. 日常新資料與月底「月對齊自癒體系」
日常更新：維持現有的「3 日無腦滾動重洗自癒（Rolling Reconciliation）」 與當日入庫前的 0050 雙源即時阻斷機制。

月底/跨月自動排程（月真理大體檢）：

每逢跨月（例如每月 1 號凌晨），排程器自動調用 verify_history_with_0050 載入「上個月」的權威資料。

與本地 SQLite 資料庫上個月的 0050 資料進行記憶體對齊比對（Outer Join）。

自癒重試機制：

若發現量價不符或開市日期斷鏈，系統自動物理刪除本地當天損毀的 CSV 快取，並針對該特定異常日期單獨觸發重新下載、清洗與寫入（最多重試 3 次）。

重試後若再次與 API 比對成功，則順利寫入 DB。

人為排除熔斷點：若重試 3 次後依然不符，判定為重大異常，系統留存 Critical Log 訊息，中斷自動化任務，靜待人工排查。

極致清理與物理備份：若整月比對 100% 完美通過，系統自動觸發全庫物理壓縮 VACUUM; 與時間戳歷史資料庫物理備份（Backup）。
